# 보험소 — 실제 가입 준비본

기존 Netlify 디자인을 유지하며 고객·파트너·관리자 계정을 분리한 소스입니다.
현재 공개 사이트는 변경하지 않았습니다. 실제 고객 가입은 아직 열려 있지 않습니다.

## 완료한 기능
- 이메일 회원가입·로그인·로그아웃·비밀번호 재설정 코드
- 가입 동의 기록과 고객 계정 생성
- 보험설계사, 손해사정사, 변호사, 기업보험 컨설턴트, 세무사, 거점 운영자 신청
- 관리자 승인·반려·활동 정지 및 심사 이력
- 타인 정보 조회·자기 승인·관리자 권한 탈취 차단
- 기존 공개 알림 서비스 전송 및 예시 인증완료 제거
- 고객 상담·방문 희망 일정 신청과 본인 요청 조회
- 관리자 단일 담당자 배정, 고객의 담당자 확인·연락처 제공 동의 후 확정
- 전문가 배정 업무, 취소·완료 처리, 정지 전문가 접근 차단
- 한국 시간 30분 단위 일정, 동일 담당자·시간 중복 확정 차단

## 다음 실행 순서
1. Supabase 운영 프로젝트를 생성합니다.
2. supabase/001_accounts.sql → supabase/002_requests.sql 순서로 SQL Editor에서 각각 한 번 실행합니다.
3. docs/setup.md에 따라 이메일·운영 정보·약관 및 개인정보 안내를 설정합니다.
4. Netlify 계정으로 로그인해 아래 명령으로 기존 사이트의 미리보기를 배포합니다.
5. 실제 인증·역할별 접근 검증 후 운영 배포합니다.

GitHub 연결은 필수가 아닙니다. 아래 Netlify CLI 방식으로 함수까지 함께 배포할 수 있습니다.
단순 파일 업로드로는 서버 함수가 정상 배포되지 않을 수 있습니다.

```powershell
npm ci
npm run build
npx netlify-cli login
npx netlify-cli deploy --build --site 533ed108-fde4-4514-b6a1-a0f510d76424
# 미리보기와 환경 설정을 확인한 다음 운영 배포
npx netlify-cli deploy --build --site 533ed108-fde4-4514-b6a1-a0f510d76424 --prod
```

## 검증 기록
- 로컬 PostgreSQL 호환 엔진: 고객 간 격리, 신청자 자기 승인 차단, 관리자만 심사 가능, 승인·정지 상태와 감사 기록 검증 통과.
- 설정 누락 및 비밀키 입력 시 가입 비활성 검증 통과.
- Edge 브라우저: 비활성 가입 화면, 가입 요청 생성, 비로그인 관리자 차단 통과. 인증 서버 응답은 모의 처리했고 실제 메일을 보내지 않았습니다.
- 실제 Supabase 메일, 운영 데이터베이스, 원격 배포는 미검증입니다.

## 미완료 범위
상담·예약 배정과 연락처 동의 흐름은 로컬 구현·검증 상태입니다. 실제 고객을 받으려면 원격 DB 적용과 운영 환경 검증이 필요합니다.
지도에서 실제 제휴 거점 선택, 전문가 가용 일정 설정, 달력·CRM, 자동 알림, 결제·정산, 카카오/PASS 연동은 후속 개발입니다.
운영 약관과 개인정보 안내는 자리표시자이며 완성된 법률 문서가 아닙니다.
방문예약 주소는 관리자가 확인 후 배정 시 입력합니다. 지도에서 실제 거점을 골라 예약하는 기능은 아직 연결하지 않았습니다.
연락처 제공 목적·수신자·보유 기간 및 삭제 절차를 확정하고 개인정보 안내에 반영한 뒤 접수를 활성화해야 합니다.
