# 화면 전환 성능 개선 — 2026-10-23

## 원인과 변경
- 홈의 member/visit/support-badge, 메뉴·계정의 support-badge가 Supabase SDK·회원 공통 코드를 각각 포함했다. esbuild ESM splitting으로 중복 코드를 해시 공통 모듈로 분리했다. 동일 문서에서는 모듈/클라이언트가 공유되고 다음 페이지에서도 다운로드한 해시 모듈을 재사용한다.
- 해시가 있는 `/assets/chunks/*`만 immutable 1년 캐시. 진입 JS/HTML에는 이 규칙을 적용하지 않는다. 빌드마다 생성 chunk 폴더만 검증된 경로에서 정리하고, 모든 클라이언트 출력에 기존 비밀키 패턴 검사를 적용한다. 생성물은 Git 제외.
- 메뉴는 서버의 현재 사용자·회원/관리자 권한 확인 후 기본 메뉴를 먼저 표시한다. 프로필·공개 프로필 링크·업무 자료 권한은 별도로 확인해 추가한다. 선택 조회 실패는 기본 메뉴를 막지 않는다. 계정 변경 세대 검사와 로그아웃/다른 탭/BFCache 보호를 유지한다.
- `/api/config`는 익명 서버 요청의 공개 설정 허용 목록만 반환한다. 성공 응답에 Netlify CDN 10초 캐시를 적용하되 브라우저 `Cache-Control: no-store`는 유지한다. 실패/비활성 응답은 캐시하지 않는다. 공개 서비스 설정의 반영에는 최대10초 지연이 생길 수 있다. 역할·고객·예약 데이터/관리자 API 캐시 및 DB·권한 변경은 없다.
- 관리자 본문을 더 일찍 노출하는 시도는 동일 계정 인증 재확인 검수에서 충돌하여 최종 코드에서 철회했다. 관리자 초기 숨김·서버 권한 확인과 본문 표시 순서는 기존 그대로다.

- help-entry:360/390/430/1440px 홈 진입·지도 프로필·상담 요청 목적·필터 전환 통과(현재 화면/클래식 지도 모듈 대상; 공통 번들은 help-login으로 별도 검수).
- 기존 불일치:map-controls-browser.cjs:21이 `#cardBody a`를 단일 링크로 가정해 strict mode 실패. 이미 HEAD의 미오픈 보험소 카드에 전문가 활동신청/주변 전문가 보기 두 링크가 존재하고 이번 변경은 해당 마크업/지도 코드를 수정하지 않는다. 범위 외 테스트 기대값은 수정하지 않았다. 해당 전체 검수 통과로 표시하지 않는다.
- 180ms 가상 API 지연의 1회 비교에서 전문가 메뉴 표시시간은1703→1851ms로 오히려 흔들렸다. 일반 화면 전환시간을 일정 비율 개선했다고 주장하지 않는다. 부가 요청을 의도적으로 멈춰도 메뉴가 사용 가능한지와 실제 전송량/공개 설정 캐시를 별도로 검증한다.
- 변경 전 운영 `/api/config` 읽기3회:2757/1139/1125ms, 모두 CDN miss/bypass. 네트워크 상태·콜드 스타트의 영향이 있으므로 SLA나 동일 네트워크 반복 통계가 아니다.
- 실제 예약·승인·삭제·결제·발송 시험 없음. 전체 npm test/npm run verify 및 실휴대전화 성능 측정은 이번 작업 범위에서 재수행하지 않았다.
