# 우리곁에 보험소 브랜드·도움 진입 UX 변경 보고 (2026-09-22)

1. 브랜드: 사용자 HTML의 로고 보조 문구·헤더·페이지 제목을 우리곁에 보험소로 변경. 페이지별 og:site_name 및 홈 title/description/OG 추가. 내부 식별자, 인증 저장 키, API 경로, DB 기존 필드는 유지. PWA manifest는 기존 프로젝트에 없음. 운영 주체 OPERATOR_NAME은 법적 운영자 값이므로 브랜드로 임의 덮어쓰지 않음.
2. Hero 전/후: “보험이 막막할 때, 내 곁에 보험소.” → “예방은 보건소에서, 보험금 청구는 보험소에서.” 기존 네이비 그래픽 유지. 서브카피는 “보험이 급한 순간, 가까운 보험 전문가가 바로 곁으로.”
3. 카피: “지금 도움받기” → “무슨 일이 있으셨나요?” → 8개 상황 → “지금 도움을 받을 지역”. 보험검진은 샘플 보조 서비스로 표시. 개설 구상 지도의 자동 배정 안내를 제거하고 실제 전문가 찾기로 연결.
4. 지금 가능: 009 마이그레이션과 인증된 등록 확인 전문가 전용 상태 저장 RPC 추가. 지금 가능 1시간 / 오늘 가능 KST 자정 만료 / 예약 가능 / 상담 불가. 권한은 기존 등록 검증 기준 사용. 만료 후 예약 가능으로 전환하여 표시. 목록은 1분마다 표시 갱신. 구 DB에서는 기존 available에 따라 예약 가능/상담 불가로 보수적으로 표시. 009 적용 전 새 상태 저장은 동작하지 않으며 실패 안내 표시.
5. 위치 UX: 기존 동의/거부 후 지역 선택 유지, 동의 철회 시 위치 제거, 조회 중 동의 철회도 확인. 지도에 현재 위치 추가. 카드와 팝업에 가능 상태 및 거리 표시(1km 미만 m). 고객 좌표 서버 저장 없음.
6. 자동매칭: 현행 DB에서 automatic=false만 허용하며 자동 배정 없음. 새 자동매칭을 추가하지 않음. availability.js에서 가능 상태 → 거리 정렬을 독립 관리. 분야/지역은 기존 catalog 필터 유지. 시간·방식·배정량·수락률·완료율 점수는 구현하지 않음. 사용자가 직접 선택.
7. 주요 파일: public/index.html, find.html, account.html, account.css, coverage.js, script.js; 전체 공개 HTML 브랜드; src/directory.js, availability.js, profile-editor.js, workflow.js, membership-consent.js, account.js; supabase/009_planner_availability.sql. 전체 동의는 선택 항목 포함을 명시하며 개별 선택 및 부분 동의 표시를 연동. 선택 동의 없이 가입 가능 유지.
8. 모바일: Edge 360px 홈→CTA→상황→목록→상태 필터, 넘침 검사, 샘플 비활성, 전체/부분/선택 동의 검증 통과. artifacts/brand-home-mobile.png, brand-consent-mobile.png.
9. 회귀: 기존 가입 동의/이메일·복구 리다이렉트/OAuth 준비 상태/관리자 비인가 차단 테스트 통과. 모바일·PC 요청→설계사 수락→일정 확정→고객 완료, 독립 광고 구독/환불 흐름 통과. PGlite와 모의 인증·PG이며 실제 이메일·PG 테스트 결과가 아님.
10. 남은 범위: 지금 통화/바로 만나기는 기존 요청·수락·일정 조율 방식. 실시간 전화 연결이나 즉시 도착 보장 아님. 기존 30분 이후 예약 제약 유지. 현재 지원 직군 목록과 수도권 지역 범위 유지. 실존 전문가/실시간 운영 검증은 별도 필요.
11. 출시 전: 009 SQL을 기존 DB 백업 및 테스트 프로젝트 검증 후 순서대로 적용, 승인된 실제 전문가 계정으로 상태 설정→로그아웃 목록→만료/거부 검증, 실제 회원가입·동의·로그인 및 연락처 동의 흐름 확인. 법적 운영자와 약관은 실제 정보 기준 검토. 그 뒤 승인된 배포 진행. 이번 작업에서는 운영 DB 변경·공개 배포·실결제를 실행하지 않음.
