# 대표 로그인 제한 (2026-10-23)

- 기존 운영 이메일 대표와 인증된 휴대전화 로그인은 서로 다른 기존 계정이며 둘 다 가입/동의 완료. 이메일 계정만 현재 관리자이고 다른 관리자는 0명. 계정 병합·신규 가입·필수동의 대행 없음.
- scripts/admin-owner-logins.sql: UUID에 고정한 private 대표 로그인 등록부와 인증된 auth.users 식별자의 현재 일치를 함께 검사. 사용자 메타데이터나 화면 이메일 비교로 권한을 부여하지 않음.
- private.is_admin은 기존 admin_memberships + ACTIVE 조건을 유지하고, 대표 등록부 또는 대표의 명시적인 최신 ADD 감사 기록을 요구. 기존 테이블에 임의로 들어간 관리자 행만으로는 접근 불가.
- 기존 admin_access_command를 재사용: 대표만 운영자 추가/해제, 일반 운영자는 추가 권한 없음, 두 대표 로그인 모두 제거 보호. 미래 운영자는 기존 가입/이메일 확인 후 대표가 기존 관리 화면에서 이메일과 사유로 추가한다.
- 개인 연락처와 운영 UUID는 공개 코드에 넣지 않음. 운영 전화 대표 등록 SQL은 ignored artifacts/admin-owner-operating.sql에만 준비. 운영 계정/인증/가입 상태 재검증 후 한 트랜잭션으로 적용, 실패 시 롤백.
- 승인 범위 밖인 073 등 대기 SQL 자동 적용을 피하기 위해 scripts/의 명시적인 수동 SQL로 분리. 기존 migrate 워크플로·DB 연결 설정 변경 없음. 적용 원장은 admin_owner_logins_20261023.sql로 기록 예정.
- src/admin-access.js: 이메일이 없는 대표 행에 ‘휴대전화 로그인’ 표시. 관리자 목록 이외의 가입/로그인 화면 변경 없음.
- 검수: 신규 격리 DB2항목 및 기존 owner-admin2항목 통과(운영자 명시 위임/해제, 대표 보호, 미인증·변경된 연락처 거부, 다른 UUID의 같은 전화번호 거부, 메타데이터 위조 거부, private 테이블 접근 거부). admin-access 격리 브라우저와 build 통과.
- 운영 적용/실로그인은 최종 인수인계 기록 참조. 운영 전문가 승인·개인정보 조회·결제·발송 시험 없음. 404 두 함수는 운영 pg_proc에도 없음 확인; 별도 적용 안 함.

- 후속 운영 read-only 검사: 두 대표의 관리자·대표·회원 판정과 my_membership.admin true, 다른 계정/익명 false, 등록부 직접 조회권한 차단 확인. 웹의 실제 로그인 세션으로 수행한 검사와 구분한다.
- 초기 실행문자열의 달러 구분자 변환 오류는 실패 상태로 중단. 수정 후 전체 운영SQL 격리 실행 통과 후 운영 재실행 성공.
- 브라우저 초기 화면 실측과 메뉴 미노출 확인. 인증 후 실제 메뉴·로그아웃·계정 전환/실휴대전화는 아직 미확인. OTP/문자/메일을 시험 발송하지 않음.

- 기존 Google 로그인 세션으로 실제 이메일 대표 로그인 및 admin.html 인증 후 본문 표시 확인. 승인/저장 버튼을 누르지 않음. 고객 데이터 원문은 보고/캡처에 포함하지 않음.

- 이번 후속은 읽기 검수와 사용자 요청 로그인 인증만 수행. 추가 코드/DB 수정 또는 배포 없음. 실기기 브라우저 화면 자체 검수는 별도.
