# 연락·사후관리 / 예약 운영시간 (2026-09-28)

## 구현
- 014_private_contact.sql: 선택/배정된 전문가 한 명에게만 연락처 공개. 동의 버전/시각, 번호 열람 로그, 원자적 상태 변경, 설문/신고/검토, 연락처 파기.
- 기존 목록은 phone 필드를 재귀 제거. 거점 예약의 새 번호는 기존 bookings.phone에 저장하지 않음. 기존 전화번호도 목록 API로 반환하지 않음.
- contact.js: 신청 동의 팝업, 전문가 연락처 열람/상태, 고객 설문/신고, 관리자 경보/후기/열람로그/제재 연결.
- 24시간 미연락 표시. 낮은 평점(3건 이상 평균3미만), 신고2건 이상 검토 플래그. 실제 경고/정지/제명은 기존 관리자 제재 기능에서 사유 기록 후 처리. 평점은 지도 기존 정렬에 반영.
- 예약: KST 10:00–18:00 운영, 시작10:00~17:00, 1시간 단위. 과거/범위 밖/비정시 서버 거부. 기존 예약 시간은 보존.

## 검증
- tests/contact.test.mjs: 동의, 지정1인, 타 전문가/관리자/거점 열람 거부, 멱등 신청, 열람로그, 상태/설문/경보/평점, 파기, 거점배정/재배정 차단.
- tests/contact-browser.mjs: 팝업→전문가열람→연락함→상담완료→고객설문→관리자 경보/로그, 모바일360px.
- tests/booking-hours.test.mjs: 10/17시 허용, 9/18시·30분·과거 거부.

## 범위/제한
- 로컬 PGlite 더미 계정 전용. 010-0000-XXXX 예시번호만 받음. 공개배포/실회원/실결제 OFF. 원격 Supabase 마이그레이션 미적용.
- 알림은 화면내 목록/5초 갱신이며 문자·푸시·이메일 전송 아님. 미연락 알림은 페이지 조회 시 계산; 닫힌 화면의 외부 알림 없음.
- 자동 제재 대신 관리자 검토 플래그. 미확인 신고로 자동 정지하지 않음.
- 배정 후 재배정은 거부: 새 수신인에 대한 재동의 절차는 후속 작업.
- 시간대는 희망 예약 접수. 거점별 동시 수용 인원/휴무일/중복 시간 재고 관리 미구현.
- 구형 통합테스트의 신청 fixture는 contact_consent/contact_phone/contact_version을 추가해야 함.
- 변경 파일: supabase/014_private_contact.sql, src/test-flow/contact.js, database.mjs, ui.js, scripts/test-flow.mjs, public/test-flow.css, 위 테스트 3개.
