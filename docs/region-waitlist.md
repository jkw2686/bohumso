# 지역 오픈 알림 신청

- `042_region_waitlist.sql`은 기존에 비어 있던 번호에 새 파일로 추가했다. 기존 040~046을 다시 실행하지 않고 이 파일과 `047_region_waitlist_retention.sql`만 순서대로 적용한다.
- 둘 다 트랜잭션이며 재실행 가능하다. 회원·승인·상담·예약·Storage 정책은 변경하지 않는다.
- 비로그인 신청은 `region_waitlist('join', payload)`만 사용한다. 반환은 자기 신청 순번 하나다. `counts`는 기존 `private.is_admin()` 검사를 통과한 관리자만 이용한다. 직접 테이블 접근은 차단한다.
- 지역·역할·연락처 중복은 최초 시각·동의·선택값을 변경하지 않는다. 순번은 시각과 UUID 순이다. 연락처 잠금과 지역/역할 잠금으로 신규 일일 한도와 순번을 직렬화한다. 일일 한도 날짜는 UTC다.
- 소비자·설계사 모두 같은 양식이다. 도움 선택은 `src/urgent.js`의 `purposes`만 사용한다. 전화번호는 기존 인증과 같은 공통 정규화 함수를 사용한다.
- 지도 개설 예정 거점에 신청 버튼을 제공한다. 방문상담 검색은 등록 전문가나 운영 거점이 없는 지역에서만 알림 버튼을 표시한다. 일시적인 OFF만으로 미오픈이라고 표시하지 않는다. 서비스 목록에 없는 시·군·구 검색어도 신청할 수 있다.
- 동의 버전은 서버 고정 `2026-10-09`. 별도의 알림 발송 기능은 없다. 개인 정보를 설계사에게 전달하지 않는다.

## 보관과 정리

- 기존 pg_cron 방식으로 매시 15분 `private.expire_region_waitlist()`를 실행한다. `notified_at`이 있거나 `created_at < now() - interval '1 year'`인 신청만 삭제한다. 다른 테이블은 대상이 아니다. 조건 충족 후 다음 실행 시 정리되므로 최대 약 1시간 지연될 수 있다.
- 실제 오픈 안내 완료를 확인한 운영자가 제한된 DB 관리 경로에서 해당 신청 ID의 `notified_at`을 발송 완료 시각으로 기록한다. 번호를 관리자 화면에 노출하거나 발송 완료 전에 임의 기록하지 않는다. 함수 직접 호출로 즉시 정리할 수도 있다.
- 신규 데이터 삭제는 복구되지 않는다. 운영에 적용하기 전 새 공개 함수 권한과 이 정리 조건을 확인한다.
- 데이터 보존 원복: UI 변경을 되돌려 새 빌드하고 아래 SQL로 접수만 차단한다. 보관기한 준수를 위해 정리 작업은 유지한다. 테이블 및 기존 신청은 삭제하지 않는다.

```sql
begin;
revoke execute on function public.region_waitlist(text,jsonb) from anon,authenticated;
commit;
```
