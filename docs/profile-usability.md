# 전문가 프로필 입력·지도·상세보기 개선

## 적용 상태

- 개발 브랜치 `codex/profile-usability`, 기준 `f361043`.
- 운영 DB 변경·공개 배포·실사용자 프로필 수정 없음. 기존 약속 관리 개발분을 보존하고 프로필 관련 파일만 수정했다.
- DB 구조·함수·Storage 정책을 바꾸지 않았다. 기존 선택 프로필 RPC, 본인 사진 API, 192px JPEG 처리와 접근 권한을 재사용한다.
- 요금·무료기간·노출 조건·상담 및 보험소 ON/OFF 기준을 변경하지 않았다.

## 확인된 원인

1. 기본 인물 SVG와 사진을 같은 아바타에 함께 만들었다. 홈·지도 마커는 프로필 사진과 별도로 기본 인물 마크를 고정 사용했고 목록 사진 로드 실패 대체 표시도 없었다.
2. 공통 프로필 렌더러에서 소개를 무조건 40자로 잘랐다. 상세보기 링크는 같은 사람의 상세 화면이 아니라 기존 목록으로 이동했다.
3. 선택 입력 화면의 소개가 취급 구분보다 앞섰고, 중앙 자동 자르기만 지원했다. 저장 버튼은 변경 유무를 구분하지 않았고 저장하지 않은 변경에 대한 이탈 확인이 없었다.
4. 기존 `fieldset label` 규칙이 전체 편집 영역의 레이블을 가로로 배치해 좁은 화면에서 사진 조절·소개 입력 폭이 줄어들었다. 해당 영역만 세로 배치로 보완했다.
5. 사진 API는 이미 버전별 URL과 `no-store`를 사용한다. 문제를 캐시 헤더 오류로 단정하지 않았으며, 저장 직후 편집 화면 및 다른 열린 지도 화면의 데이터를 갱신하도록 보완했다.

## 변경 내용

### 입력과 저장

사진 → 보험 취급 구분 → 도움 업무 → 소개 순서. 선택 입력 유지, 경력 추가 없음. 소개는 여러 줄 높이의 입력칸과 현재 글자 수를 표시한다. 기존 40자 초과·줄바꿈 소개는 그대로 읽고 보관하며 다른 항목 저장 시 소개를 전송하지 않는다.

신규 소개를 바꾸어 저장할 때는 기존 서버 규칙(줄바꿈 없는 일반 문장, 40자 이하)을 유지한다. 개행을 저장하는 새 기능은 추가하지 않았다. 화면에서 길이와 입력 오류를 먼저 알려준다. 상세보기에서는 저장돼 있는 소개의 줄바꿈·이모지·긴 문장을 전체 표시한다.

`저장하기`를 주요 동작으로, 사진 변경·삭제·취소를 보조 동작으로 정리했다. 변경 없음·저장 중·성공·실패를 구분한다. 저장 중 입력과 중복 요청을 차단하고, 실패 시 입력·선택 사진을 유지한다. 소개 저장 후 사진 저장만 실패한 경우 부분 저장 상태를 명시한다. 변경 취소와 화면 이동·새로고침 시 확인을 제공한다.

### 사진

기존 사진 정규화·압축을 재사용하며 미리보기에서 끌기, 가로/세로 위치 조절, 확대, 90° 회전을 지원한다. `이 사진 사용` 후 `저장하기`를 눌러야 전송된다. 조절 취소는 저장 사진에 영향을 주지 않는다.

정사각형 192px/128KB 이하 JPEG를 지도 48px, 상세 96px로 사용한다. 사진과 인물 SVG는 상호 배타적으로 렌더링한다. 실패 시 같은 크기의 기본 아바타로 대체한다. 본인 편집 화면은 기존 인증 사진 API를 사용해 비공개 상태의 사진도 확인할 수 있게 한다.

사진 버전 URL을 그대로 사용하고 저장 알림에는 시각만 담는다. 다른 열린 지도 탭과 복귀 화면이 최신 공개 목록을 읽도록 했으며, 주소·연락처·사진 원문을 브라우저 저장소에 추가 저장하지 않는다.

### 지도·상세보기

홈 지도·지도 페이지·목록의 지도에 같은 인물 사진 마커를 사용한다. 보험소 집 아이콘은 유지한다. 같은 지역 기준점의 마커는 56px 간격으로 분리하고 선택은 사진 바깥 외곽선으로 표시한다. 공개 활동지역 기준이며 현재 GPS라고 표시하지 않는다.

사진·이름·`프로필 보기`가 같은 전문가의 상세창을 연다. 지도 카드 하단에 `프로필 보기`와 `상담 요청`을 바로 표시한다. 상세창은 현재 지도 위에서 열고 닫기·Esc·브라우저 뒤로가기로 복귀한다. 지도 중심·확대 수준·선택 카드를 유지한다.

상세 순서는 사진·이름·소속 → 취급 구분 → 도움 업무 → 소개 → 상태·기존 요청/방문예약. 없는 선택 항목은 숨긴다. 연락처 등 공개 불필요 정보는 추가하지 않는다. 본문 자체가 스크롤되고 버튼은 문장 다음에 배치돼 마지막 문장을 덮지 않는다.
