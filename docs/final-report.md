# 보험소 작업 결과 보고

상태: 로컬 기능 구현·통합검사·프로덕션 빌드 검증본. 실제 배포 및 실결제 없음. 실제 Supabase와 토스 테스트 상점 연결은 미검증.

## 1. 기존에 구현되어 있던 기능
정적 HTML/CSS/JavaScript와 esbuild 기반 화면, 수도권 개설 예정 지도, 샘플 보장분석/진단, Supabase 이메일 가입·로그인·비밀번호 재설정, 가입 동의, 파트너 신청, 관리자 심사, 역할별 상담 요청 목록이 있었다. 실제 PG는 없었다. 기존 Netlify 디자인과 페이지를 유지했고, 별도 프로젝트로 다시 만들지 않았다.

- 지도 마커 프로필 연결, 거리순 정렬, 위치 거부 시 지역 선택, 좌표 미등록·지도 배경 실패 안내.
- 설계사 수락·패스·일정 제안, 고객 일정 확정 및 선택 설계사 연락처 제공 동의.

- 같은 예약의 일정 변경·후속 미팅, 추가 과금 없음.
- 문의·분쟁·노쇼·환불 상태, 관리자 근거·처리자·시간 이력, 잔금 미결제 시 신규 수락 제한.
- 토스 테스트 전용 카드결제 어댑터, 승인·조회·서버 검증·동일 멱등키 재시도·주문별 전액 환불·웹훅 재조회. 라이브 키 차단.
- 관리자 요약·필터·설계사별 실적·무료 현황·가격 정책·등록 확인·결제/환불/분쟁 메뉴.
- 완료한 상담의 후기만 제출 가능하며 공개 동의 및 관리자 검토 후 노출. 샘플 후기와 실적은 해당 샘플 프로필에 표시된다.

## 4. DB 변경사항
001/002는 그대로 보존했다. 003은 프로필, 가격 정책, 새 상담, 무료 이용권 상태, 연락처 동의, 이벤트, 후속 일정, 후기, 이의 제기, 주문·거래 시도 테이블을 추가한다. 004는 단계별 주문/승인/환불 RPC, 005는 만료 제안 재배정, 006은 익명 방문 세션과 관리자 지표다.
민감 테이블 직접 읽기·쓰기를 차단하고 제한된 RPC로 접근한다. PG 결과 반영은 서버 service_role만 가능하다. 단계별 주문 유일성, payment_key 유일성, 예약 시간 중복 제약과 예약/설계사 행 잠금을 사용한다.
기존 예약 데이터는 삭제하지 않고 조회 전용으로 유지한다. 구형 일방 완료 API는 신규 정책을 우회하지 못하도록 쓰기 권한을 제거했다.

## 5. 자동매칭 로직
교체 가능한 private.rank_planners / private.specialty_match 함수로 분리했다. 기본 점수는 전문 분야 적합도 40, 동일 지역 30, 요청 가능 상태 10이다. 최근 배정량을 감점하고 현재 이력 기반 수락·완료 비율을 가산하며, 위치 동의와 좌표가 있으면 근거리 후보를 우대한다. 이미 확정된 동일 시간, 미확인/정지 설계사, 요청 중지, 유효 미결제 잔금, 이전 패스 후보를 제외한다.
직접 선택 건은 임의로 재배정하지 않는다. 자동매칭 동의 건만 패스 또는 응답 기한 경과 후 다음 후보를 한 명씩 제안한다. 후보가 없으면 매칭실패/전문가 모집 중으로 표시한다. 응답 기한은 24시간, 작업 주기는 15분이며 실제 작업 활성화는 하지 않았다.
상담가능 시간 설명은 프로필 안내이고, 초기 일정 적합성 검사는 예약 충돌과 양측 확인을 사용한다. 주간 시간표 자동 예약은 이번 범위에 넣지 않았다.

- PostgreSQL 호환 PGlite: 고객 격리, 파트너 승인, 권한 탈취 차단, 무료 배정 한도, 고정 가격, 중복 시간, 고객 완료 확인, 미결제 제한, 노쇼 복원, 자동매칭·패스·만료·실패, 후속 무과금, 후기 검토, 환불 재시도, 지연 통지, 방문 지표 접근 검증.
- 결제 모듈: 라이브 키 거부, 금액/주문/결제키/통화/수단 검증, 중복 승인, 승인 타임아웃 후 조회, 불확실 거래 보류, 멱등키, 카드 데이터 저장 제외.
- API: 비활성 설정·잘못된 origin·비로그인 요청·위조 웹훅 힌트를 외부 결제 없이 차단/무시.
- Edge 모바일 390px 및 PC: 가입 화면 회귀, 로그인, 지역/지도, 위치 거부, 직접 상담 요청, 무료 미팅, 유료 동의, 두 주문 모의 카드결제, 고객 완료 확인, 자동매칭 패스·다음 후보·취소, 비관리자 차단.
- 프로덕션용 브라우저 번들과 Netlify 서버 함수 번들을 빌드했다. 실행 결과는 artifacts/verification-report.json, build-report.json에 저장한다.
- 인증과 PG는 모의 응답이다. 실제 메일·토스 테스트 승인·외부 웹훅은 검증하지 않았다. 실제 DB의 독립 연결 간 경합 부하검사는 별도로 필요하다.

## 7. 발견한 오류와 수정
기존 설계사 일방 완료/관리자 배정 흐름을 새 소비자 선택·고객 완료 확인 흐름으로 연결했다. 구형 API 우회 경로를 닫고 기록을 남겼다. 신규 SQL의 구분자 오류를 테스트로 발견해 수정했다. 늦은 1차 승인 통지가 전액 완료/환불 완료를 되돌리는 상태 충돌을 막았다. 결제 승인 불명확 상황을 실패로 단정하지 않고 조회 대기로 유지한다. 기존 샘플 날짜를 KST로 변경했고 지도 좌표 미등록·배경 로딩 오류의 대체 안내를 추가했다.

## 8. 현재 남아 있는 문제·한계
현재 Supabase URL/서버 키 및 토스 테스트 키가 설정되지 않았다. 따라서 실제 테스트 상점 결제가 작동한다고 아직 확인할 수 없다. 사업자·운영자 정보와 운영 약관/개인정보 안내는 확정 전이며 가입/결제는 기본 비활성이다. 지도는 외부 타일 제공 상태의 영향을 받지만 목록으로 이용할 수 있다. 전체 외부 SMTP/웹훅/운영 권한 검증은 남아 있다. 조회는 최근 200건이고 대규모 운영용 페이지 분할·장기 보관/삭제·고급 정산은 이번 파일럿 구현 범위 밖이다.

## 9. 실제 배포 전에 필요한 작업
테스트용 Supabase에 마이그레이션 적용, 이메일 인증 실제 수신, 테스트 역할 교차 접근, 토스 테스트 키 연결과 승인/취소 검증, 사업자 및 설계사 실확인, 동의·보유·환불 정책 확정, 기존 진행 예약의 이관 계획을 완료해야 한다. APP_ORIGIN과 인증 리다이렉트 URL을 최종 주소에 맞춘다. bohumso.netlify.app은 아직 확보하지 않았다. 공개 배포는 별도 승인 전까지 하지 않는다.
