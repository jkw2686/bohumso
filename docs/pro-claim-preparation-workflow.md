# 보험소 PRO 청구준비 Workflow — 현행 기준

사용자 정정 요청을 반영한 기준입니다. 이 업무에 관한 이전의 사전 출력·종이 위임장 지참 가정보다 우선합니다.
로컬 가상 MVP 구현을 추가했습니다. 고객·병원·서류 선택, 만료·재발급 링크, 기기 내 직접 마스킹, 사본 준비 완료의 실시간 반영과 독립된 자필서명 상태를 체험할 수 있습니다. 실제 문자 발송·운영 인증·실서류 처리는 연결하지 않았습니다. 공개 배포·실사용자 오픈은 하지 않습니다.

## 기본 흐름

고객 상담 → 병원서류 대리발급 필요 확인 → 설계사가 보험소 PRO에서 기존 상담 고객 선택 → 병원 선택 → 필요한 서류 선택 → [고객에게 서류 준비 요청] → 고객 휴대폰으로 Secure Link 전달 → 고객이 링크 접속 → 필요한 최소정보 확인 → 신분증 촬영 → 개인정보 보호처리/마스킹 → 신분증 사본 준비 완료 → 설계사 화면에 즉시 완료 표시

- 상담 전에 대리발급 필요 여부가 확정되어 있다고 가정하지 않습니다.
- 설계사가 사전에 위임장·동의서를 출력하거나 지참하는 것을 기본 절차·필수 조건으로 두지 않습니다.
- 고객은 이미 선택한 전문가와의 상담 맥락에서 요청을 받습니다. 자동 매칭이나 여러 전문가에게 정보 분배를 추가하지 않습니다.
- 병원·필요서류·청구상황은 설계사가 입력한 요청 정보를 재사용합니다. 고객에게 같은 정보를 다시 입력시키지 않습니다.
- 고객에게는 필요한 최소정보만 확인하게 합니다. 현장 입력을 최소화하고 불필요한 자유입력란을 추가하지 않습니다.

## 고객 화면

> 병원서류 준비
>
> ○○병원
>
> 담당 전문가가 병원서류 준비를 요청했습니다.
>
> 약 1분 정도 소요됩니다.
>
> [신분증 촬영]

병원명·필요서류는 읽기 전용 정보로 전달합니다. 필요한 설명은 접어서 볼 수 있게 하고, 정보가 다르면 담당 전문가에게 수정을 요청할 수 있게 합니다. 다시 병원을 선택하거나 청구상황을 작성하는 절차는 넣지 않습니다.

촬영 → 마스킹 결과 확인 → 신분증 사본 준비 완료를 짧은 흐름으로 제공합니다. 마스킹에 실패하거나 사용자가 결과를 확인하지 않았다면 완료 처리하지 않습니다. 원본 사진을 올렸다는 사실만으로 개인정보 보호처리 완료로 표시하지 않습니다.

## 독립 상태

| 대상 | 상태 | 완료의 의미 |
| --- | --- | --- |
| 요청 전달 | 발송 대기 / 발송 확인 / 전달 실패 / 만료 / 취소 | 발송 결과만 표시. 고객의 열람·작업 완료와 구분 |
| 신분증 사본 | 준비 요청 / 촬영 / 보호처리 중 / 결과 확인 / 준비 완료 / 재촬영 필요 | 필요한 보호처리를 거친 사본 준비만 완료 |
| 위임장 | 필요 여부 확인 중 / 자필서명 필요 / 종이 원본 확인 필요 / 후속 확인 완료 / 해당 없음 | 확인 근거 없이 자동 완료하지 않음 |
| 동의서 | 필요 여부 확인 중 / 자필서명 필요 / 종이 원본 확인 필요 / 후속 확인 완료 / 해당 없음 | 위임장과 별도로 관리 |

설계사 화면 예시:

- ✓ 신분증 사본 준비
- ⚠ 위임장 자필서명 필요
- ⚠ 동의서 자필서명 필요

신분증 사본을 준비하면 디지털 작업의 완료 상태를 즉시 반영합니다. 자필서명이나 종이 원본이 남아 있어도 신분증 작업 자체는 완료할 수 있습니다. 반대로 신분증 준비 완료를 위임장·동의서 완료, 병원서류 발급 완료, 병원 접수 승인으로 표시하지 않습니다.

자필서명·종이 원본은 설계사 후속 작업 목록으로 분리합니다. 필요한 문서, 남은 행동, 확인 여부가 보이게 합니다. 담당자가 확인한 후속 작업은 담당자·시각·확인 근거를 기록합니다. 필요 여부가 아직 불명확한 항목은 ‘확인 중’으로 유지합니다.

## 전자위임장

현재 MVP에서는 전자위임장의 병원 인정 여부가 검증되지 않았습니다. 따라서 전자위임장 완료를 필수 단계나 다음 단계 진입 조건으로 사용하지 않습니다. 병원 인정 여부가 확인된 것처럼 표시하지 않습니다. 병원별로 추가 확인이 필요한 요구사항은 설계사의 후속 작업으로 안내합니다.

## Secure Link 및 개인정보 구현 조건

아래는 구현해야 할 조건이며, 현재 연결 완료를 뜻하지 않습니다.

- 고객·담당 전문가·해당 요청에 접근 범위를 제한하고, 인증된 권한 확인 없이 다른 요청의 자료를 조회할 수 없게 합니다.
- 추측하기 어려운 만료·폐기 가능한 링크를 사용합니다. URL에 고객명·전화번호·청구상황·신분증 정보를 넣지 않습니다. 링크 발급과 실제 메시지 발송 성공을 구분합니다.
- 링크가 만료·취소되면 명확히 안내하고 설계사 재요청 절차를 제공합니다. 링크를 다시 발급하면 이전 링크를 폐기합니다.
- 원본 신분증은 가능한 한 기기에서 처리하며, 원본을 서버에 보내는 것을 기본값으로 하지 않습니다. 실제 수집 범위·마스킹 기준·보유 및 삭제 정책을 확정하기 전에는 가상 자료만 사용합니다.
- 필요한 자료만 비공개로 처리합니다. 사진·등록정보·링크 토큰을 분석 로그나 공개 URL에 남기지 않습니다. 서류 열람·삭제 권한을 구분합니다.
- 서버가 준비 완료를 확인한 뒤 설계사 화면에 즉시 반영합니다. 연결 실패 시 완료를 가장하지 않고 동기화 상태와 재시도를 제공합니다.
- 중복 전송·새로고침이 중복 요청을 만들지 않게 하고, 취소된 요청이 늦은 응답으로 다시 완료되지 않게 합니다.

## 구현 시 수용 기준

1. 설계사가 위임장·동의서를 미리 출력하지 않아도 서류 준비 요청을 만들 수 있다.
2. 고객에게 병원·필요서류·청구상황을 다시 입력시키지 않는다.
3. 신분증 사본 준비를 마치면 담당 전문가 화면에 해당 항목만 즉시 완료 표시한다.
4. 위임장·동의서의 자필서명과 종이 원본은 각기 독립된 후속 작업으로 남는다.
5. 전자위임장 미완료로 신분증 사본 준비가 막히지 않는다.
6. 보호처리 실패·전송 실패·링크 만료·취소를 완료로 표시하지 않는다.
7. 다른 고객이나 다른 전문가가 요청 자료를 볼 수 없다.
8. 지인 테스트는 가상 자료로 진행하고 공개 배포·실사용자 오픈을 하지 않는다.

핵심: 현장에서 디지털로 바로 처리할 수 있는 것은 즉시 끝내고, 종이 원본·자필서명이 필요한 것은 후속 작업으로 분리합니다.
