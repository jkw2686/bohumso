# 상담 접수·연락 후 확정

## 사용자 요청과 적용 범위
- 전문가 본인이 상담 접수 ON/OFF. 방문 상담은 별도 위치 동의와 기존 종료시간 유지. OFF 시 새 접수와 새 방문 검색 중단, 접수한 예약 보존.
- 보험소 접수는 현재 지정된 관리자만 ON/OFF. 실제 운영 주소·좌표·영업시간 등록을 마친 보험소만 ON 가능. 개설 예정 거점은 이번 변경으로 운영 상태가 되지 않음.
- 새 일반 예약과 방문 요청: 요청 → 담당자 수락 → 양측 연락처 공개 동의 → 양측 전화·연락 완료 확인 → 고객 최종 확정.
- 인증된 번호만 사용. 양쪽 동의 전에는 서버도 번호를 반환하지 않음. 관리자 목록에 새 상담의 전화번호를 추가 공개하지 않음. 방문 주소는 기존과 같이 고객 최종 확정 이후에만 담당 전문가에게 공개.
- 연락 완료는 양측 자기 확인이며 실제 통화 기록을 수집하거나 통화 여부를 자동 판정하지 않음.
- 기존 완료·확정 예약의 진행 방식을 소급 변경하지 않음.

## 알림
- 운영 `private.notifications`와 본인 전용 `notification_inbox` 재사용. 기존 기록 보존.
- 요청·수락·연락 동의·연락 완료·확정·일정 변경·출발·도착·완료·취소·만료 단계의 인앱 알림. 양측 모두 자신의 알림함에서 확인. 담당자 없는 보험소 요청은 기존 보험소 직원/관리자 수신 대상 유지.
- 화면에서 30초마다 갱신. 앱을 닫아 둔 상태의 SMS/외부 푸시는 이번 작업에 포함하지 않음. 실제 사용자에게 검증용 문자/알림을 보내지 않음.
- 알림 본문에 전화번호·주소·건강정보를 저장하지 않음.

## DB
- 049: `office_locations.booking_enabled`, 두 예약 테이블 `contact_flow` 추가. 기존 행 0, 신규 행 2.
- private.contact_permissions: 상대방·예약·동의 버전·시각·인증번호 지문. 원본 전화번호를 이 테이블에 복제하지 않음. 기존 consent_records에도 append-only 동의 증빙.
- private.contact_acknowledgements: 상대방·예약·일정별 연락 확인. 일반 예약 일정/담당자가 바뀌면 새 확인 필요.
- 두 신규 테이블 RLS 켜기, anon/authenticated 원본 접근 차단. 공개 RPC는 활성 회원의 자신의 요청만 처리. 이전 내부 래퍼 직접 호출 차단.
- 기존 Google/SMS 공급자 설정, 관리자 명단, Storage 정책, 회원·전문가 승인 상태 변경 없음.
- 050: 운영 알림 구조를 재사용하며 신규 설치에도 같은 테이블을 만들 수 있음. 기존 알림 데이터 삭제 없음.
- 049/050은 배포 시 외부 BEGIN/COMMIT 하나로 묶어 실행. 함수/열/RLS·회원 1건은 private.contact_flow_backup에 실행 전 한 번 저장. 전체가 실패하면 변경 전체 취소.
- 기존 열 삭제/타입 변경/회원·예약 삭제/TRUNCATE 없음. 재실행 검사 포함.

## 복원
- 배포 전 기준: `6c140ff` (운영 코드 `49a4a6b`).
- `supabase/rollback_contact_first.sql`: 새 방식 신청/동의가 없을 때 기존 함수 복원. 데이터·추가 열은 삭제하지 않음.
- 새 신청/동의가 존재하면 연락처 보호가 약해지는 복원을 차단. 이 경우 새 요청을 멈추고 기존 보호 래퍼를 유지하면서 수정 배포.
- 동의 증빙 보관은 현재 개인정보처리방침의 운영팀 기간 관리 절차를 따름. 자동 파기 범위를 새로 확대하지 않음.

## 검증 상태
- 격리 SQL: 재실행, 실제 역할별 RPC, 일반 상담·방문상담, 양측 동의/연락/확정, 번호 위조 무시, 일정·인증번호 변경, 종료 후 비공개, 권한 격리, OFF 신규 접수 차단 및 기존 상담 보존 통과.
- 실제 화면과 격리 SQL 연결: 고객·전문가·관리자 흐름, 스위치 저장, 키보드, 알림 확인 및 해당 예약 이동, 320/360/390/768/1440px 통과. build 통과. 운영 변경 전 회원 4 / 프로필 2 / 일반·방문 예약 0 / 운영 보험소 0 / 알림 0 확인.
- 운영 적용·배포 결과는 완료 후 HANDOFF에 기록. 실제 회원의 문자·통화·GPS·예약은 실행하지 않음.
